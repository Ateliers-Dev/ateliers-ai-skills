# 指示の確認と競合解決

> 作成日: 2026-11-16
> 更新日: 2026-11-19
> 作成者: yuu503

この文書は、リポジトリの規則と Skill の指示が競合した場合の共通手順を定めます。各作業の具体的な手順、権限、制約は、作業対象リポジトリの規則に従います。

## 適用される `AGENTS.md` の確認

- 作業対象がリポジトリの場合は、作業を始める前に対象リポジトリと作業対象のパスを特定し、そのパスに適用される `AGENTS.md` を確認します。リポジトリのルートから作業対象までの各親ディレクトリに加え、リポジトリのルートより上位にある作業環境の規則も、その適用範囲に応じて確認します。
- 作業対象がリポジトリではない場合、`AGENTS.md` を探す必要はありません。
- 適用される `AGENTS.md` が見つからない場合は、存在しないことを理由に作業を止めず、ほかの適用される指示に従って通常どおり進めます。
- 確認できないファイルやアクセスできない範囲があり、それが作業の安全性・権限・手順に影響する場合は、その影響する作業を止め、確認できた範囲と未確認事項を記録して判断を委譲します。

## Skill の指示と競合した場合

- まず、より上位の指示と適用される安全・権限上の制約を守ります。`AGENTS.md` も Skill も、それらを上書きしたり、新たな操作権限を付与したりするものではありません。
- それらの範囲内で `AGENTS.md` と Skill の指示が競合する場合は、`AGENTS.md` を原則として優先します。競合していない Skill の手順は引き続き適用します。
- `AGENTS.md` に従うと上位指示や安全・権限制約に反する場合、または競合を安全に解決できない場合は、該当する作業だけを停止します。問題の内容、従えない理由、影響範囲、可能な代替案を記録し、権限のある上位判断主体へ判断を委譲します。
- 判断の委譲先を「人間」に限定しません。各リポジトリの規則に定められた権限ある主体・経路を使用し、決定が得られるまで競合する作業を再開しません。

## 記録と報告

競合または確認不能によって作業を止めた場合は、確認した規則とその適用範囲、競合箇所、停止した作業、理由、代替案、必要な判断を簡潔に記録して報告します。未確認事項を確認済みとして扱わず、競合の影響を受けない安全な作業は続けられます。
