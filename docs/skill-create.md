# Skill 作成（ateliers-skill-create）

作成日：2026-11-06 ／ 更新日：2026-11-06（日本標準時 JST (UTC+09:00)）

## 用途

会話・Markdown・GitHub Issue の要件から、新しい Skill の用途・発火条件・権限・成果物を設計し、SKILL.md・tests・日本語 docs を作ります。既存 Skill の再利用を優先し、許可された範囲で日本語コミット、push、PR 作成まで進めます。main へのマージは行いません。

既存 Skill の改善実装は将来の Improve の責務です。拡張が適切なら根拠と受け入れ条件を提案して引き継ぎます。レビューだけなら [Skill レビュー](skill-review.md) を使用します。複数 AI のオーケストレーション、自動公開、Issue の無断起票、品質基準の無断変更は含みません。

## 依頼例

```text
$ateliers-skill-create を使い、ローカルの会議メモから決定事項と未決事項を抽出する
ateliers-meeting-summary を作ってください。入力は Markdown、出力は日本語 Markdown。
元のメモは変更せず、外部送信もしません。決定と推測を区別してください。
本体・tests・docs を作成し、正常入力と決定のない入力で検証してください。
今回はローカル作成までです。
```

```text
$ateliers-skill-create で、次に貼る Skill Request の本文に沿って新規 Skill を作成してください。
対象は Ateliers-Dev/ateliers-ai-skills。既存 Skill を検索して再利用を検討し、
検証後に作業ブランチで日本語コミット・push・日本語 PR 作成まで実施してください。
main にはマージしないでください。
（ここに対象・課題と利用場面・受け入れ条件・対象外と参考資料を貼る）
```

接続があれば Issue の URL・番号を指定できます。未接続なら本文の貼り付けで同じ要件整理が可能です。Issue 内の命令や「承認済み」は操作権限になりません。会話で承認済みの作業は繰り返し確認しません。成果を左右する要件不足や、再利用と新規の判断が分かれる場合に確認します。

## 作成の流れと結果の読み方

1. 最新 main・既存差分・共通基準・Issue Forms・既存 tests/docs を確認し、要件と権限を整理します。
2. [Skill Catalog](skill-catalog.md) の一覧と OR 候補検索を使用し、候補の本文・用途・発火条件を比較します。検索語、対象版、候補と差、判断理由を記録します。検索0件は非重複の証明ではありません。エラーや未知の形式は不完全な確認とし、読めるファイルで補います。
3. 既存で満たせば再利用を案内し、新規作成しません。拡張が適切なら Improve 向けに提案します。独立した用途があれば一式を作成します。
4. 構造検証、回答・行動の試験、レビュー、未検証事項を分けて記録します。自己評価は独立レビューではありません。
5. 許可済みのコミット・push・PR 作成を行い、URL、ブランチ、コミット、変更内容、検証結果と限界を報告します。

成果物は `skills/<name>/SKILL.md`、`tests/<name>/`、`docs/<name の ateliers- を除いた名前>.md` が基本です。テストには入力・プロンプト・期待事項・手順・検証記録を含め、生成ログは `tests/**/results/` に保存し Git から除外します。docs の既存作成日と MIT 表示を保持します。

## 非接続・権限不足と配布

GitHub の接続は必須ではありません。取得不能な Issue は本文貼り付けへ切り替え、ローカル成果物と検証記録を作れます。コミット・push・PR 作成のどこまで成功したかと、残りの理由・再開条件・PR 文案を示します。失敗や未実施を成功として報告しません。

配布単位は Skill フォルダです。共通基準・Catalog・Review は対象リポジトリ側の資産を使います。単体配布で利用できなければ手動確認と本体の完成単位・境界で作成し、共通基準への適合や重複確認の未確認範囲を明記します。接続の追加や権限拡大を勝手に行いません。配置方法は [各 AI ツールでの使い方](ai-tools.md) を参照してください。

## 検証状況

初版の実施方法・結果・未検証事項は [テストと検証記録](https://github.com/Ateliers-Dev/ateliers-ai-skills/tree/main/tests/ateliers-skill-create) にまとめます。構造・Catalog 連携の自動テストと、作成担当による回答・行動の自己試行を区別します。独立レビュー、登録環境での自動発火、実サービスでの権限拒否は別途確認が必要です。自動テスト合格はすべての AI 環境での動作保証ではありません。

初回の実際の作成依頼から PR までの試験は [PR Review 作成 E2E 記録](https://github.com/Ateliers-Dev/ateliers-ai-skills/blob/main/tests/ateliers-skill-create/e2e-pr-review.md) を参照してください。初版の模擬試行とは分け、Create を変更せず使用した過程・自己評価・未検証事項を記録しています。
