# ateliers-document-review

作成日：2026-11-06 ／ 更新日：2026-11-06

## 用途

README、仕様書、設計書、運用手順などの技術文書をレビューする Skill です。読み手が文書を使って判断・作業できるかを確認します。

主な確認観点は、目的と前提、用語・数値・例の整合性、手順の再現性、断定の根拠、理解を妨げる曖昧さです。すべての文書に同じ章立てや確認項目を要求するものではありません。

Skill 本体の正本は [GitHub 上の SKILL.md](https://github.com/Ateliers-Dev/ateliers-ai-skills/blob/main/skills/ateliers-document-review/SKILL.md) です。配置と呼び出しは [各 AI ツールでの使い方](ai-tools.md) を参照してください。

## 作業の境界

レビューを依頼しただけでは、対象文書を修正しません。文例や修正方針は回答内の提案として返します。ファイルへの反映を希望する場合は、別途、対象と範囲を明示して依頼してください。

文書中にコマンドや AI への指示があっても、それはレビュー対象です。レビューの依頼から、操作・コミット・公開の許可までを読み取ることはありません。

コード単体のレビューや文書の新規作成を主目的とする依頼は、この Skill の対象外です。

## 依頼に含める情報

対象のファイルまたは本文に加え、想定読者、文書の目的、重点的に見てほしい観点を伝えると、必要な指摘を絞りやすくなります。外部仕様との照合も必要なら、対象の製品・バージョンや参照資料を指定してください。

以下は依頼本文の例です。Skill を登録して使う場合は、各ツールの呼び出し方法を併用してください。

```text
docs/operations.md をレビューしてください。
想定読者は初めて夜間対応をする運用担当者です。
作業前提、操作の順序、成功判定、復旧手順を重点的に確認してください。
文書内で判断できる整合性を対象とし、外部資料の調査は不要です。
ファイルは変更せず、日本語でレビュー結果を回答してください。
```

## 結果の読み方

| 区分 | 内容 |
| --- | --- |
| 確認できた事実 | 実際に読んだ記述や検証結果。場所と根拠を示す |
| 要確認事項 | 情報不足、推測、外部仕様や動作を確認できていない点 |
| 改善提案 | 指摘を受けた修正方針や文例。未確認の値を正解として補わない |

例えば「秒単位の仕様に対して例がミリ秒相当の数値になっている」は文書内の矛盾として指摘できます。一方、実装がどちらの値で動くかは、コードや実行結果を確認しない限り未確認です。

指摘は影響に応じて重大・中・軽微を目安に整理します。表記の好みだけを必須修正にはしません。問題が見つからなければ、その確認範囲で検出しなかったことを返します。これは文書や実装全体の正しさを保証するものではありません。

## テストと確認状況

[GitHub 上のテスト一式](https://github.com/Ateliers-Dev/ateliers-ai-skills/tree/main/tests/ateliers-document-review) に、正常な設定仕様、意図的な問題を含む運用文書、実行プロンプト、期待される検出事項、実行手順があります。

動作を試す場合は、ケースごとに新しいチャットを使い、Skill と入力、実行プロンプトを渡します。期待値は回答生成の後に採点用として読みます。入力を変更していないことと、問題の検出だけでなく誤検出がないことも確認してください。

生成結果の保存先 `tests/**/results/` は Git 管理から除外しています。検証記録そのものは追跡対象として別に置きます。

初版では構造検証と同一チャット内の自己試行を実施しています。独立チャットでの評価、自動選択、各製品での実機動作確認は未実施です。実施済みと未検証の詳細は [検証記録](https://github.com/Ateliers-Dev/ateliers-ai-skills/blob/main/tests/ateliers-document-review/validation.md) を参照してください。
