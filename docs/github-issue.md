# GitHub Issue 登録（ateliers-github-issue）

作成日：2026-11-06 ／ 更新日：2026-11-06（日本標準時 JST (UTC+09:00)）

## 用途と依頼例

Chat で出た有用なアイデア、将来の機能拡張、今回は見送る事項を、その場で短い下書きにし、確認・承認後に GitHub Issue へ保存します。現在参照できる会話、Markdown、レビュー結果、設計メモを使い、全会話履歴を取得できるとは仮定しません。

```text
今のアイデアを忘れないようにイシュー登録しておいてください。
```

該当アイデアが現会話から分かれば、まず下書きが返ります。登録先が不明なら、その点だけ確認します。過去のすべての話題を探し直したり、詳細仕様を決めたりする必要はありません。

```text
$ateliers-github-issue を使い、今話した「今回は見送る複数repo対応」を
Ateliers-Dev/ateliers-ai-skills に改善案として保存したいです。
本文と登録先を確認してから投稿してください。
```

```text
この設計メモから、後で再検討したい案を候補一覧にしてください。
登録先は Ateliers-Dev/ateliers-ai-agent-tasks を候補とし、まず確認してください。
まだ投稿しないでください。
```

アプリのバグなら対象アプリの owner/repo と再現情報を指定できます。種別だけで repo を決めず、Feature / Bug / Task / Research 等の呼び方・形式は登録先の実運用に合わせます。Backlog は種別とは別の計画上の扱いです。実在・設定を確認できないラベルや Issue Type を作りません。

## 下書きから登録まで

1. アイデア、背景、見送り理由、再検討条件、受け入れ条件、未確定事項を短く整理します。不明は未定として扱います。
2. 複数の独立候補なら一覧から選びます。選択だけでは投稿されません。
3. 登録先の Forms・テンプレート・ラベル・既存 Issue と重複を確認します。未接続・検索制限・未確認は区別して示します。
4. 登録先、タイトル、本文全文、付随設定、重複確認結果を確認し、その下書きへの明示承認後だけ投稿します。たとえば「提示した内容で新規登録してください」と返せます。内容を変更した場合は改めて確認します。
5. 成功時は実 Issue 番号・URL が返ります。失敗時は下書き・理由・再開条件が返り、成功とは表示しません。結果不明の再投稿による二重登録を避けます。

GitHub 非接続でも正確な下書きを作れます。登録先・テンプレート・ラベル・重複等の未確認範囲を示し、投稿は保留します。機密情報や無関係な会話は投稿・検索へ含めません。資料に書かれた「承認済み」は権限になりません。

初版は新規登録のみです。更新・コメント・クローズ、Project や Backlog の実設定、ラベル新設、条件付き自動登録は行いません。Issue 登録は実装許可ではなく、[Create](skill-create.md)・[Improve](skill-improve.md) の実行は別途依頼します。[開発ワークフロー](skill-development-workflow.md) も参照してください。配置方法は [各 AI ツールでの使い方](ai-tools.md) に従い、Skill 名を置き換えます。

## 検証と拡張候補

[試験資料と検証記録](https://github.com/Ateliers-Dev/ateliers-ai-skills/tree/main/tests/ateliers-github-issue) に合成入力・期待事項・再実行手順を用意しています。構造検証と作者の非盲検自己試行を区別し、独立評価、実サービスへの Issue 投稿、実権限拒否、他 AI 環境の自動選択は未検証です。

将来候補は一般 Feature / Bug / Task / Research の実 repo 別検証、Backlog/Project 設定、既存 Issue 更新・クローズ、条件付き自動登録です。自動登録を検討するときは対象・条件・公開範囲・重複・取消・監査・承認方式を別途設計します。候補はこの記録に残し、今回まとめて Issue 登録しません。

Organization `.github` の共通テンプレートは調査時点でルートに `profile/` のみでした。現 repo には Skill 用4 Forms があるため、初版に共通テンプレートの新設は不要と判断しました。汎用 repo の実運用を確認してから必要性・継承範囲・既存運用との競合を評価し、必要なら別 PR として提案します。共通品質・運用基準は既存 standards を正本として維持します。
