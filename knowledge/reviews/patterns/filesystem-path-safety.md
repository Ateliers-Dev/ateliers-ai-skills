# ファイルパスの安全性を確認するレビュー観点

作成日：2026-11-06 ／ 更新日：2026-11-06（日本標準時 JST (UTC+09:00)）

## 対象技術・適用条件

利用者や設定からパスを受け取り、ファイルを列挙・コピー・更新・削除する変更に適用します。インストーラー、同期・配置ツールなどが対象です。ファイル操作を含まない PR に一律適用しません。

出典は [PR #9 の事例](../cases/pr-0009-path-validation.md)です。Windows、PowerShell、.NET の事例を一般化しています。ドライブ相対、UNC、デバイスパス、ReparsePoint、大文字小文字の扱いは Windows 固有の条件を含むため、他 OS・ファイルシステム・ランタイムでは仕様に合わせて再検証します。

## 根拠・確認状況

[最初の修正](https://github.com/Ateliers-Dev/ateliers-ai-skills/commit/01e419a732b8398d9703f2767b53aac9656dac79)と[デバイスパス修正](https://github.com/Ateliers-Dev/ateliers-ai-skills/commit/880909d50e629877ff8b9cc7f214e9f039c35980)から導いたレビューの問いです。修正コードの静的確認と、独立部分検証・作者・ユーザーの報告を根拠とします。各報告の範囲と未確認事項は出典事例に保持しています。この文書自体の作成で動作検証は追加していません。

以下の入力はレビュー用の例で、実在する作業先や実行指示ではありません。危険なコピー等は隔離した一時領域や原因部分の検証で扱い、実データへの副作用を避けます。

## 1. パス解決の基準と入力形式

- **適用条件：** パスを利用者入力・設定・環境変数から取得する。
- **確認する問い：** 相対入力は何を基準に解決するか。シェルの現在位置、プロセス作業ディレクトリ、スクリプト位置の違いで結果が変わらないか。既定値と明示入力は同じ仕様か。曖昧な形式を解決するか、拒否するか。
- **入力例：** `.\skills`、`C:skills`、`\skills`、`C:\outside\skills`、`\\server\share\skills`、空文字、引数省略。
- **必要な証拠：** 受け付ける形式の仕様、使用 API と解決基準、現在位置とプロセス作業ディレクトリを変えた結果、拒否理由。既定値と明示入力の両方を確認する。
- **限界：** PR #9 での「完全修飾パスに限定」はそのツールの設計判断。相対パスを使う全ツールへの拒否義務ではない。
- **出典事例：** PR #9 の相対パス誤解決と最初の安全性修正。

## 2. 正規化・形式検証の順序と別表現

- **適用条件：** 入力を正規化した後に許可・拒否や包含を判定する。
- **確認する問い：** 形式検証と正規化で同じ表現を見ているか。区切り文字を変えるだけでデバイス名前空間を通常の UNC として扱わないか。拒否はコピー等の副作用より前か。
- **入力例：** `//?/C:/repo/skills/target`、`//./C:/repo/skills/target`、`\\?\C:\repo\skills\target`、`\\.\C:\repo\skills\target`、混在区切り文字、`C:\repo\outside\..\skills`。
- **必要な証拠：** 修正前の誤判定と修正後の期待結果、実装が使う API での確認、実際のテスト用コピー元内部を指す入力、専用の拒否理由。無関係な例外を成功扱いしない。
- **限界：** 文字列の置換だけで全別名や実体の同一性は保証できない。入力形式の仕様と実際の OS の解釈を照合する。
- **出典事例：** PR #9 の `//?/`・`//./` 回避と final head の修正。

## 3. コピー元・先の一致、包含、区切り文字境界

- **適用条件：** 再帰列挙、コピー、同期などで入力と出力の領域が重なる可能性がある。
- **確認する問い：** 同一領域やコピー元内部への出力で、再列挙・再実行時に出力を入力へ取り込まないか。保護すべき境界はコピー元だけかリポジトリ全体か。単なる文字列接頭辞で似た名前の兄弟まで拒否しないか。
- **入力例：** コピー元を `C:\repo` とした一致、`C:\repo\skills\nested`、`C:\REPO\skills`、`C:\repo\x\..\skills`、兄弟 `C:\repo-sibling`、末尾区切り文字の有無。
- **必要な証拠：** 正規化後の一致・区切り文字境界の比較、OS に応じた大文字小文字の扱い、深い配下の拒否と兄弟の許容、再実行時の結果。判定部分の再現と実コピーの観測を分ける。
- **限界：** 包含が許される設計もある。PR #9 のリポジトリ全体拒否を一律の仕様にしない。実コピーをしていない場合、再帰増殖や汚染を再現済みとは書かない。
- **出典事例：** PR #9 の包含チェック欠落と修正・境界テスト。

## 4. リンク、ジャンクション、検証後の状態変化

- **適用条件：** 親階層・コピー元・既存の書き込み対象にリンクが入り得る。
- **確認する問い：** 見かけのパスと実体が違わないか。親階層と対象内部の両方を見るか。検査後から書き込みまでに対象が差し替わる場合、何を保証できるか。
- **入力例：** コピー先の親のジャンクション、既存 Skill 内のジャンクション、書き込み経路のシンボリックリンク、検査後の差し替え。
- **必要な証拠：** 検査箇所と実際のリンクを作った拒否結果、環境・権限、未実施ケースと理由。競合への対策または制約を確認する。
- **限界：** 属性の静的検査は実動作の証拠ではなく、TOCTOU 防止の保証でもない。権限不足による skip を pass に数えない。
- **出典事例：** PR #9 のリンク拒否3ケースの未実施と、同時変更に関する制約。

## 5. スキップ、WhatIf、途中失敗を副作用で確かめる

- **適用条件：** 同一内容のスキップ、更新時刻による保護、ドライラン、部分成功がある。
- **確認する問い：** 再コピーしても成功するテストになっていないか。WhatIf がファイル作成・内容・時刻変更をすべて抑止するか。途中失敗時に、残った変更とエラーが正しく報告されるか。
- **入力例：** 同内容で時刻だけ異なるファイル、異内容でコピー先が新しい・同時刻・許容差内のファイル、存在しないコピー先への WhatIf、既存ファイルへの WhatIf、途中のコピー失敗。
- **必要な証拠：** 前後の内容・更新時刻・作成有無、コピー先だけのファイルの保持、成功済み変更の残存と最終エラー。要件を破る実装をテストが検出できる条件を用意する。
- **限界：** ログの「スキップ」表示や終了コードだけでは副作用なしを証明できない。時刻精度・許容差・巻き戻し仕様は対象に合わせる。
- **出典事例：** PR #9 の同一内容スキップのテスト修正、WhatIf・部分失敗の静的確認。

## 6. 証拠の範囲と未実施を分ける

- **適用条件：** レビュー結果や検証結果を保存し、マージ判断や後続作業へ渡す。
- **確認する問い：** 誰がどの版の何を実行したか。コードの静的確認、原因部分の実行、統合テスト、作者報告、ユーザー報告、CI を混同していないか。
- **入力例：** 「両版各9項目の部分検証」「両版各13成功・リンク3未実施」「ローカル試験は問題なし、個別ログなし」「workflow と status の取得結果は空」。
- **必要な証拠：** 固定 head、環境・コマンド・結果・ログの有無、実施主体、未実施理由、対象テストを含むコマンドの定義。後続報告は時点を分けて追記する。
- **限界：** マージ済みや一般的な成功報告から、個別未確認項目や CI の成功を補完しない。観点の追加だけで欠陥の完全検出は保証しない。
- **出典事例：** PR #9 の独立部分検証、作者報告、後日のユーザー報告、GitHub マージ情報の区分。

## 使い方と更新

適用条件に合う観点を選び、対象の仕様と証拠を対応づけてレビューします。新しい実例で有効性や例外が分かった場合は、[入口の更新方法](../README.md)に従い出典事例と確認状況を追加します。この文書を唯一の編集正本とし、Skill 配下の同梱資料は機械生成します。6観点の利用に出典事例の取得は必須ではありません。Skill 本体の条件付き参照・フォールバックと行動評価は Phase 3 PR B で扱います。
