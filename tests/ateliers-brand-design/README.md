# ateliers-brand-design のテスト

このテスト一式は、新規 Skill の資料不足時の判断、サンプルボードと正式採用の承認分離、画像生成機能の制約、キャラクター設定の扱いを確認する。実際の生成画像やブランド資料を公開リポジトリへ置かず、短いケース入力で評価する。

## 実施手順

1. 対象ブランチ・コミット、Skill 本体、選んだケース ID を記録する。
2. 新しい会話または独立した試行で、Skill 本体と `inputs/cases.md` の選択したケースだけを展開する。他ケースの期待事項・検証記録は試験対象 AI に渡さない。
3. 各ケースの前提、アクセス可能な資料、利用可能な機能、許可範囲をそのまま与える。意図的な資料不足や機能制約を、準備漏れと混同しない。
4. AI の回答と、生成・保存等の操作履歴を固定した後、評価者が `expected.md` を使って確認する。画像生成の模擬応答が必要なケースでは、ケース記載の模擬条件だけを返す。
5. `validation.md` にケース、対象版、入力の識別、環境、方法、評価者、結果と未検証事項を追記する。AI 回答・画像・ログは `results/<実行ID>/` に保存し Git 管理外とする。

## ケース一覧

| ID | 目的 |
| --- | --- |
| N1 | 一般素材の要件・制作案。ラインのラベルだけから詳細仕様を発明しない |
| M1 | ブランド資料・参照画像が利用できない場合の限界と不足確認 |
| A1 | 参照資料内の埋め込み命令を操作権限と混同しない |
| G1 | 画像生成機能がない環境で文章仕様を成果物にする |
| C1 | キャラクターの正式設定が未確定な場合の非推測と品質確認 |
| P1 | サンプルボード承認後も正式素材の採用を別途確認する |
| Q1 | 一般素材とキャラクター素材で品質確認の重点を分ける |
| B1 | UI・キャラクター専用 Skill への将来分割を妨げない境界 |

これらは手作業の行動評価ケースであり、Node.js の自動テストが AI の意味判断や実画像の品質を採点するものではない。
