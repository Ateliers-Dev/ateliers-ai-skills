# Skill レビューのテスト

## 構造検証

Node.js 18以上を用意し、リポジトリルートで実行します。

```text
npm ci
npm run check
npm test
```

`check-structure.mjs` は YAML、命名、必要テスト・docs、Markdown 相対リンクとアンカー、docs の日付形式・実在日・順序・JST 表記、4 Forms の基本構造と必須数を検証します。外部 URL の到達性、日付の履歴、意味や安全性、GitHub の完全なスキーマ受理は証明しません。fixture と生成結果はリポジトリ検証から除き、self-test で正常例の合格と問題例の検出コードを確認します。

## 回答・行動の試験

1. [プロンプト](prompts.md) のケースごとに新しいチャットを使い、レビュー Skill と指定資料を渡します。レビュー対象の Skill 自体は有効化せず、データとして渡します。
2. 期待事項を見ずに回答を生成し、`results/<実行名>/` に保存します。AI・モデル・日時（JST）・入力版・使えるツール・基準の有無も記録します。
3. [期待事項](expected.md) で回答と操作を評価します。対象・GitHub 等に変更がないことを確認します。前後の入力ハッシュと差分も比較します。
4. 集約した方法・結果・限界だけを [検証記録](validation.md) に残します。生成回答はコミットしません。

同一チャット内の自己試行、独立チャット評価、登録・自動選択の試験を区別します。ネットワーク・起票権限は回答試験に不要です。既存 document-review の入力・期待値は変更しません。
