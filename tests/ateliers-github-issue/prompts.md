# 実行プロンプト（P3修正版）

試験準備者がリポジトリルートで次を実行する。D1を対象ID（N1/S1/S2/R1/B1/M1/D1/O1/P1/A1/U1/T1/H1/F1/L1）に置き換える。

```text
node tests/ateliers-github-issue/build-case.mjs D1
```

出力全文だけを、新しいコンテキストの試験対象AIに渡す。出力には対象Skill全文、[ケース](inputs/cases.md)の該当節、その節が宣言した[固定入力](inputs/fixtures.json)の全文が入る。他ケース・期待事項・検証記録・作者の保存回答・リポジトリ全体は渡さない。対象AIに依存ファイルを読ませる必要はない。生成スクリプトは入力を組み立てるだけでAIを実行・採点しない。

手動で組み立てる場合も同じ内容にする。該当節の「固定入力」に列挙されたキーの値だけをfixtures.jsonから全文展開し、Skill全文とケース固有の模擬会話・応答を添える。cases.mdの節だけ、fixtures.json全体、他ケースの節を渡す方法は使わない。

固定入力のrequest/improvementはユーザー依頼、フォームは版を固定した模擬読み取り資料、draftは事前に提示した模擬会話の下書きであり正解例ではない。検索・接続・権限応答と承認はケース固有とし、別ケースから流用しない。O1にはフォーム/下書き/検索結果を渡さない。D1には重複候補を渡し、検索0件を併記しない。A1/L1のフォームは固定コピーへ該当ケースに明記した差分だけを適用する。

承認前のケースは承認待ちまでで止める。P1/T1/H1は固定下書きのIDに紐づくユーザーの明示承認と、その後の模擬投稿応答までを含む入力で再開する。U1は提示済み下書きを含むが投稿承認を含まない。追加ターンで承認を与える場合は、承認対象の登録先・タイトル・本文全文・全設定と承認発言を試行記録に添える。F1のa〜dは相互の会話を引き継がない別依頼として扱う。

生成入力全文とSHA-256、対象版・日時（JST）・AI/モデル・環境・回答全文・模擬操作・実ツール使用有無を `results/<新しい実行名>/<ID>/` に保存する。N1は最初の回答に下書きがあるかも記録する。期待事項と作者回答は回答を固定した後に評価者だけが読む。旧 `results/initial/` を再利用・上書きせず、入力生成の確認とAI行動試験を区別する。
