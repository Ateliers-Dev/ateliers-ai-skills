# GitHub Issue 登録のテスト

共通基準は [品質](../../standards/quality.md)・[運用](../../standards/workflow.md) を参照。[入力](inputs/cases.md)、[固定fixture](inputs/fixtures.json)、[入力生成](build-case.mjs)、[実行プロンプト](prompts.md)、[期待事項](expected.md)、[検証記録](validation.md) を一組で使う。

1. 対象版、日時（JST）、AI・モデル、環境、接続・許可を記録する。
2. 実行プロンプトに従い `node tests/ateliers-github-issue/build-case.mjs <ID>` の出力全文だけを新しいコンテキストへ渡し、各ケースを独立実行する。実サービスへ投稿しない。期待事項・検証記録・作者回答は試験対象AIへ先渡しせず、回答固定後に評価者が採点する。
3. 回答全文、確認質問、模擬操作とその理由、実ツール呼び出しの有無を `results/<実行名>/` に保存する。生成結果はGit管理外。
4. 期待事項ごとに採点し、自己試行・独立試行・構造検証を区別する。未実行は未検証と書く。
5. リポジトリルートで `npm ci --ignore-scripts` 後に `npm run check`、`npm test`、`git diff --check`。Catalog固定一覧6件と入口・日付・Forms維持・results除外も確認する。

自動検証は既存の構造・Catalog等を使う。AI行動を自動実行するテストや投稿モック実装は追加していない。入力生成は指定された固定データと1ケースだけを結合し、期待事項・作者回答を読み込まない。初版の作者回答・自己採点は旧入力の履歴として維持し、P3修正版の合格証拠にしない。変更後の試験は新しい実行名で記録し、入力生成の確認・非盲検自己試行・独立行動試験を区別する。

実接続の読み取りは許可範囲で別途検証できる。実投稿試験は承認済みの専用repo・本文・設定がある場合のみ別に実施する。この試験一式や開発依頼は具体的なアイデアIssueの投稿許可ではない。更新・クローズ・自動発火の試験は初版対象外。
