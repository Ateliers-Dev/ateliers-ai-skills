# ateliers-design-review のテスト

技術記事用概念図の独立レビューについて、画像の実観察、技術・ブランド根拠、要件照合、承認境界、誤検出を確認する。画像Fixtureはテスト専用に作成した架空の図で、Ateliersの正式素材・実制作画像を含まない。架空ブランドガイドもケース限定の非公式資料である。

## 実施手順

1. 対象ブランチ・コミット、Skill版、ケースID、環境、評価者を記録する。
2. ケースごとに新しい会話を用意し、Skillとケース入力だけを渡す。期待事項、検証記録、fixtureマニフェストは回答固定後まで試験対象AIへ渡さない。D6の作者評価は初回回答を固定するまで提示しない。
3. 画像ありケースは表のPNGをそのまま添付する。ファイル名とIDを明示し、期待事項にある観察点を入力側で説明しない。添付不能は準備失敗として記録し、画像ありケースの合否を付けない。
4. D1/D5/D6ではASP.NET Core 10.0公式資料を一次資料として参照する。ネットワークや参照資料の不足があれば、技術領域の未検証報告を採点する。
5. D9では架空ガイド全文と明確な非公式・ケース限定の状態を展開する。正式なブランド資料として扱わない。
6. 回答と観察できた操作を固定してから `expected.md` とマニフェストを使って評価する。回答、ログ、画面記録は `results/<run-id>/` に保存しGitに追加しない。
7. `validation.md` に対象SHA、ケースID、画像IDとSHA-256、参照資料・版、環境、モデル（分かる範囲）、評価者、結果、未実施範囲を記録する。

| ケース | 添付 | 条件 |

| D1, D4, D5, D6 | `fixtures/images/DR-MVC-FLAWED-001.png`（ID同名） | 問題を含む版 |

D1/D2/D4/D5/D6/D8/D9の要件、版、架空ブランド資料、期待事項はケース入力・ガイド・このテスト手順で固定する。D1/D2/D9は画像あり／修正後／架空ガイドの中核ケース。D3は画像なし。D4/D5はそれぞれブランド／技術資料不足を分離する。

## 静的検査とAI行動試験

`node tests/ateliers-design-review/check-fixtures.mjs` はPNG形式、寸法、SHA-256、ケースID、期待事項の対応を検査するだけで、画像の意味やAIレビュー品質を評価しない。AI行動試験は、新しい会話で実画像を添付して行う。静的検査の成功、入力・画像の作成者による目視、非盲検の自己試行を独立したAI行動試験とみなさない。
