# 実行プロンプト

各ケースは新しい会話で一件ずつ実施する。テスト対象に渡すのはSkill本体、選択したケース全文、およびそのケースに指定した画像・資料のみ。`expected.md`、`validation.md`、`fixtures/fixture-manifest.md` は回答固定後まで渡さない。D6は初回の独立評価を固定した後でだけ作者の自己評価を提示し、二段階を別記録にする。

```text
$ateliers-design-review を使って、次のケースだけを処理してください。
対象ケース：<ID>
<inputs/cases.mdからケース全文を展開>

<画像ケースはREADMEの対応表どおり、PNGファイルを実際に添付>
<架空ガイドを使うケースはfictitious-brand-guide.md全文を展開>

ケースに書かれた資料・権限・バージョンだけを前提にしてください。
画像が開けないときは画像を見たと主張せず、画像依存の評価をしないでください。
確認できた資料・版・日時と未確認事項を分け、操作履歴を事実どおりに報告してください。
```

D1/D5/D6のASP.NET Core 10.0照合では公式資料を使い、確認したURL・版・日付を記録する。資料へアクセスできない試行は失敗扱いではなく、その制約下で技術領域が未検証と報告されるか評価する。D2の旧指摘はケース入力として提示するが、旧版画像を添付せず、期待結果・マニフェストは渡さない。

画像を添付できなかった場合は、画像ありケースの試験準備失敗として記録する。画像を文章で説明し直して画像観察試験の代替にしない。
