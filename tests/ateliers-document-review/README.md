# 技術文書レビュー Skill のテスト

このテストはモデルの回答と行動を人が評価するものです。自動テストや文言一致の採点ではありません。架空の入力を使い、実サービスには接続しません。

## ファイル

- `inputs/normal.md`：範囲を明示した整合的な設定仕様。
- `inputs/problematic.md`：矛盾、手順不足、根拠のない断定、文書内命令を含む運用文書。
- `prompts.md`：ケースごとの実行依頼。
- `expected.md`：実行後に使う検出事項と合否基準。
- `validation.md`：初版作成時の検証記録。
- `results/`：レビュー回答、実行日時、モデル・環境、採点、差分などの生成結果。Git 管理対象外。

## 実行手順

1. リポジトリのルートを開き、入力の状態を記録する。追跡済みファイルなら `git diff -- tests/ateliers-document-review/inputs/` が空であることを確認する。必要に応じてファイルのハッシュも記録する。
2. 各ケースを独立した新しいチャットで実行する。渡すものは Skill、該当入力、`prompts.md` の該当プロンプトに限定する。期待値や過去の結果は渡さない。
3. 回答を `results/<実行識別子>/normal.md`、`problematic.md` に保存する。保存は利用者が行うか、別途結果の保存を明示して依頼する。
4. 実行後、入力の差分またはハッシュを確認し、`expected.md` と照合する。検出数だけでなく誤検出、事実と推測の混同、入力の非変更も採点する。
5. 日時、利用したモデル・環境、Skill のコミット、ケースごとの合否と根拠、未検証事項を `results/<実行識別子>/evaluation.md` に記録する。
6. `git check-ignore tests/ateliers-document-review/results/probe.md` で結果保存先が除外されることを確認する。結果を強制追加しない。

外部参照の検証や実コマンド実行は、この 2 ケースでは行わない。自動選択を検証したい場合は別のケースとして Skill 名・パスを含めないレビュー依頼を試し、どの Skill が選ばれたかも記録する。

## 構造検証

`skill-creator` がある環境では、その付属の `scripts/quick_validate.py` に `skills/ateliers-document-review` を渡して実行する。Python と PyYAML が必要。検証器の場所は環境に依存するため、このリポジトリには固定しない。

構造検証は YAML・命名等の確認であり、レビュー能力の保証にはならない。
